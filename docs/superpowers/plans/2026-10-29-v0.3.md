# Bytasm v0.3 implementation plan

Preserve the uncommitted v0.2 activity slice on main. No Git mutations or new
services/dependencies. Blueprint J7/J8/J9, §6, §7.2 and M7 define the scope.

1. Comparison: `compare.py` and `api/compare.py`, normalized category keys,
   deterministic bounded rows, explicit unavailable/incompatible provenance.
   Verify identical, changed, partial, cancelled, mismatch and cross-sample cases.
2. Annotations: analyst + immutable annotation/citation rows in migration 0005,
   same-version target/citation validation, optimistic revisions, atomic events.
   Verify citation rules, history, concurrent stale edits, rollback and upgrades.
3. Frontend: comparison selectors/category navigation and annotation forms,
   citation picking and revision history. Preserve the existing activity section.
   Verify loading, errors, plain-text escaping, keyboard and 360 px layout.
4. Reports: preserve the published v2 schema, publish schema 3 with annotations
   and optional comparison scope; reverify both blobs and cited run outputs.
   Verify deterministic schema-valid exports, tamper refusal and old downloads.
5. Integrate routers/activity links and document the chosen contracts/limits.
   Run `make check`, `make audit`, `make e2e`, `make compose-check`; run container
   upgrade smoke checks with a disposable data directory if Docker is available.

Implementation choices: one analyst `local`; note/interpretation/conclusion,
conclusions require finding/evidence citations and confidence; plain text up to
4000 characters, at most 20 citations. Same logical sample only for comparisons.
No comparison rows/events for pure reads. No historical backfill or deletion.
Comparison report is optional `compare_with` on the existing report endpoint,
using B as the base version and A as the comparison source. UI uses the existing
native controls, CSS tokens and typed client pattern.
