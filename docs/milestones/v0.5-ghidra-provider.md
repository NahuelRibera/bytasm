## Bounded implementation plan

1. Add metadata preflight tests first: missing/invalid configuration, declared
   Ghidra/Java versions, unsupported hosts, malformed/oversized/symlink/FIFO
   metadata, path privacy and proof that configured launchers are not invoked.
2. Implement read-only preflight without subprocesses, project creation or
   directory discovery. Read at most 16 KiB per metadata file, require regular
   files, reject duplicate keys and unsafe configured paths. No untrusted error
   text or path is returned/logged.
3. Add independent CLI doctor and additive Tools diagnostics using startup-read
   configuration; typed UI with genuine loading/error/blocker states, no fake
   analysis action. Keep existing tool availability/profile contracts intact.
4. Test API/CLI/no-data side effects, frontend/accessibility and existing complete
   suites. Run fixture hashes, audit, Compose checks and demo in isolated data.
   Record real-provider tests as blocked, not passed.

## Implemented contracts and constraints

Configuration is captured at startup into a separate optional configuration
object. Bad optional paths do not affect Settings validation for normal startup.
It is never derived from a request, global JAVA_HOME/PATH or a sample. Private
installation paths are omitted from configuration repr, diagnostics and logs.

The metadata checker reads only `Ghidra/application.properties` and JDK `release`,
up to 16 KiB each, requiring regular files with O_NOFOLLOW and nonblocking opens.
It checks the fixed launcher/Java file type and executable permission, without
invoking them. File type/permission/version declarations are not proof of
integrity, authenticity, compatibility or a healthy launch. No self-check exists
in this release. No environment variable can set availability true.

`bytasm doctor` emits the typed diagnostic as deterministic JSON and exits 1
while the provider is unavailable. It never creates a project/database/workspace
or opens a sample. `GET /api/v1/tools` adds `optional_providers` to the existing
response, retaining the original four tools and two profiles. The UI shows the
real metadata-only blocker with loading/error states, explicit unavailable
analysis and unperformed health check. There are no Ghidra request/run/detail
controls or invented function records. Raw filesystem errors and version strings
outside the small allowlist are never reflected.

Architecture/Java compatibility checks are metadata-only. No Ghidra analysis
format/architecture/host is declared supported. Java 21.0.12.1 was observed locally
using the already-installed Homebrew JDK's `java -version`; JDK25/Ghidra12.2 were
not installed, downloaded or launched. The current real doctor reports
`not_configured`, `available: false`, `health_check: not_run` and exit 1.
