## Behavior and rationale

The overview begins with apparent file type and declared architecture/bitness/
endianness, with links to exact identity/header evidence. Unverified publisher,
authenticity, name and authorisation remain explicit. The default source is the
latest analysis run, including failed/cancelled/active runs. Explicit `run_id`
links fetch only that run; version ID, SHA-256 and size must match. Missing or
mismatched evidence never falls back to an older success.

Completion text describes check completion within bounds, not threat severity
or complete coverage. Every check states why missing evidence remains unknown.
Rule counts require a completed rule step; Ghidra-only jobs link to bounded
function coverage instead. Up to three existing reviewed templates describe
observations and cautious hypotheses in source order, never a severity ranking.
String counts include stored/found/capped distinctions. No new interpretation
catalog, confidence score or threat verdict was added.

The overview uses GET requests only; it does not launch a parser while browsing.
Fresh analysis remains an explicit existing profile/selected-detail action.
Report snapshots retain independent selection/serialization. No DB migration,
historical report rewrite, parser/protocol alteration, dependency, tool package,
license change, remote request or sample execution is introduced.

## Security decision

A full I1 implementation cannot honestly be completed as a presentation change:
API-side basic parsing/LIEF launch, shared writable trusted state, escaped
process groups and absent independent containment/resource-exhaustion evidence
are concrete blockers. [ADR-0007](../adr/0007-guided-overview-and-i1-gate.md)
records the decision. [I1 acceptance](../security/i1-acceptance.md) reviews upload,
parsers, queue/cancel, scratch/store, environment/network, rendering, crash,
retention and deletion, with runtime probes and a next verifiable broker/VM spike.
Every I1 acceptance item is unchecked. No sandbox or platform certification.
