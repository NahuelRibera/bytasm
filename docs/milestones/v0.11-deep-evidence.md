## 2. Architecture

```
import record (LIEF 0.3.0 raw output) ──► structure_source ──► import slots ─┐
Ghidra run (ghidra-5, verified) ───────────────────────────────────────────────┤
pattern run(s) (strings, YARA-X, capa) ──► evidence_sources ───────────────────┤
                                                                              ▼
                                                    evidence_graph.build_graph (graph-2)
                                                     │                      │
                       live API (/evidence…) ◄───────┘                      ▼
                                                        evidence_snapshot.build_snapshot
                                                     │ pinned in review-3   │ in memory
                                                     ▼                      ▼
                                              evidence_compare.compare_snapshots
```

Every comparison is snapshot-to-snapshot. A `version:` side is converted to a
snapshot in memory with the same code that pins reviews, so a pinned side and a
live side are normalized identically, and a pinned side is never recomputed.

`evidence_sources.py` factors out source loading from the v0.10 API so a review
can build its graph from exactly the invocations it pinned. Each pattern tool may
come from a different run; every finding and string keeps its own run ID in its
locators.

## 3. Evidence snapshot (`bytasm-evidence-snapshot-1`)

Fields: `algorithm` (graph schema), `sample` (version, sample, SHA-256, size,
format), `scope_sha256`, `content_sha256`, `sources[]`, `address_mapping`,
`coverage[]`, `nodes[]`, `edges[]`, `bounds`, `limitations[]`.

- **Sources.** One row per tool (`lief`, `ghidra`, `strings`, `yara-x`, `capa`):
  `state`, `unavailable_reason`, run, invocation, output digest, tool and adapter
  versions, Ghidra protocol, profile and script digests, rule-set digest, and
  `retention` flags (Ghidra function count, retained, truncated, timed out,
  detailed; strings retained and truncated; findings with capped evidence).
- **Address mapping.** Declared image base and basis, Ghidra protocol, memory-map
  state and reason, Ghidra image base, rejected file ranges, map truncation.
- **Nodes and edges.** The v0.10 shapes, normalized: strings ≤ 256 characters
  with `label_truncated`, attribute values limited to scalars, lists ≤ 64 and
  two levels of maps, source locators ≤ 4 with `sources_total`, edge locators ≤ 4.
- **Two digests.** `scope_sha256` is the graph scope digest and includes database
  run and invocation IDs ("these exact stored records"). `content_sha256`
  excludes database identifiers (run, invocation, finding and string row IDs, and
  the row part of `row:` pointers) and raw-output digests ("the same evidence from
  the same inputs and tool identities"). Raw-output digests stay recorded, but are
  excluded from the content digest because capa's raw JSON embeds run metadata:
  two capa runs on identical bytes produce different raw digests and identical
  findings (found by `test_identical_inputs_give_identical_snapshot_content_across_databases`).
- **Determinism.** Canonical order uses kind, address, file offset, label and node
  ID, never `identity` (which may contain a database finding ID; an earlier draft
  ordered by it and failed the cross-database test).
- **Bounds.** ≤ 4096 nodes, ≤ 8192 edges, ≤ 1.5 MiB canonical JSON. Over a bound,
  nodes are retained by kind priority (entry point, sections, findings, functions,
  imports, external symbols, program data, strings) and canonical order; edges only
  between retained nodes, strongest first. Omissions are counted per kind and type,
  and a limitation is added. If the byte bound is still exceeded, the node budget
  shrinks deterministically (minimum 16), then the snapshot is refused.

### Review immutability

Reviews remain append-only canonical JSON with a stored SHA-256
(`ReviewSnapshot`). `bytasm-review-3` adds `evidence` and `evidence_status`. A
read validates the digest, so neither a new run, a tool upgrade, a rule change,
a changed Ghidra output nor an algorithm change can alter a pinned snapshot; the
evidence endpoints additionally recompute `content_sha256`. Creation re-verifies
every source as before; a database-mutated tool version is refused (409) instead
of being pinned. If a review with its snapshot would exceed the existing 4 MiB
review cap, the snapshot is omitted and `evidence_status` says so.

Compatibility: `bytasm-review-1/-2` documents validate unchanged (the new fields
default to `None`), export as export-1/-2 as before, and report
`not_captured_historical`. `schemas/review-v2.schema.json` and
`review-export-v2.schema.json` are unchanged; v3 schemas are new files.

## 4. Comparison model (`bytasm-evidence-comparison-1`)

Canonical identity is not correspondence. A node ID names an observation inside
one graph. Whether it corresponds to an observation in another graph is decided
only by these methods (`evidence-correspondence-1`), strongest first:

| Method | Applies to | Rule | Limitation |
|---|---|---|---|
| `identical_input_address` | functions, program data | same sample SHA-256, same Ghidra identity (version, protocol, profile, script) and same declared and Ghidra image bases | exact |
| `rule_identity` | findings | tool, namespace, rule name | rule text may differ if rule-set digests differ (reported as environment change) |
| `declared_section_name` | sections | name + ordinal among equal names; truncated names unmatched | names are declarations |
| `string_value_digest` | strings | encoding + SHA-256 of the complete value + ordinal by offset; truncated values never matched | content only, not location or use |
| `joined_string_value_digest` | program data | inherits the key of the one string it joins by exact file offset | depends on that join |
| `unique_symbol_name` | functions, external symbols | namespace::name (+external flag), unique on both sides; Ghidra default names (`FUN_…`, `thunk_FUN_…`, `DAT_…`, …) and address-fallback labels excluded | a renamed function is unmatched, never "removed" |
| `import_name`, `singleton` | imports, entry point | exact name; one declared entry point | — |

Addresses are never compared across different files or Ghidra environments: a
rebase, section shift or code change would make address equality meaningless.
Edges correspond when their type and both endpoints' keys correspond.

### Attribution

For an observation present on one side only, or present on both with differing
compared fields, the required sources are the edge's join sources plus both
endpoints' producers. Rules, in order:

1. A required source is unavailable on a side → `not_comparable`,
   `coverage_difference`. For edges, also when the edge's join was not evaluated
   on both sides.
2. The lacking side's snapshot omitted that kind at its bound → `not_comparable`,
   `retention_bound`.
3. A required source differs in tool, adapter, protocol, rules, profile or script
   → `analysis_environment_difference`.
4. The lacking side's source window was capped → `retention_bound`.
5. Same bytes: different stored outputs → `source_output_difference`;
   otherwise `identical_input`.
6. Otherwise → `binary_difference_under_comparable_coverage`, the only
   attribution that points at the file.

Modified fields per kind: section offset, size, VA and flags; entry point VA and
offset; function address (only when not matched by address), body size, block,
instruction, conditional-branch and indirect-call counts; finding match count and
rule-set digest; string offset; program-data address and offset. Edge attribute
differences make an edge `modified`.

Statements use reviewed templates with counts and cited change IDs, for example
"1 extracted string observation appears only in B under comparable coverage." or
"N rule match observations appear only in B, but the producing tool or
configuration differs; the file is not established as the cause." No statement
interpolates untrusted text, and none uses verdict language.

## 5. Deep PE/ELF structure (metadata adapter 0.3.0, `bytasm-lief-deep-1`)

Stored only in the content-addressed raw import output, not in the database
header, and re-verified on every read (digest, size bound, input identity).

- **PE.** Image base, alignments, image and header sizes, declared checksum, entry
  RVA; sections with verified raw ranges and characteristics; all 16 data
  directories with RVA, size, section, derived file offset and range state (the
  certificate table's field is a file offset, as the PE/COFF specification
  defines); import descriptors; import slots (library, name or ordinal, hint, IAT
  RVA, VA and derived file offset); exports (ordinal, RVA, forwarder flag, offset);
  relocation summary (blocks, entries by type); debug entries with verified ranges;
  TLS directory addresses and callback count.
- **ELF.** File type, entry, interpreter, GNU build ID; program headers with
  `rwx` flags, verified file ranges and section-to-segment mapping; dynamic table
  (NEEDED/SONAME/RPATH/RUNPATH text); dynamic symbols (value, size, type, binding,
  visibility, section index, imported/exported); relocations by type; import slots
  from `*_JUMP_SLOT`/`*_GLOB_DAT` relocations with file offsets derived through
  PT_LOAD headers; notes (descriptions ≤ 64 bytes).
- **Structural observations.** Factual statements about declarations: data
  directory or section raw range outside the file, overlapping section raw ranges,
  writable and executable section or segment, entry point outside sections or
  load segments or in a non-executable one, allocated section outside load
  segments. None is a verdict. No fixture triggers one.
- **Bounds.** 4096 rows per table, 64 segments, 256 dynamic entries, 1024 dynamic
  symbols, 512 relocation blocks, 32 notes and debug entries, 64 observations; caps
  listed in `truncated`. A table LIEF cannot decode yields no tables plus a
  warning, never a failed import.
- **Unchanged.** The import record's header, sections and symbols, the CLI
  `inspect` report (it excludes the new tables) and the report schema. The import
  catalog now accepts adapter 0.3.0, whose import names are unchanged. Without
  this, new imports would have silently lost their import observations.
- Existing imports keep adapter 0.2.0 output; `/structure` reports that the
  tables predate 0.3.0 and are not reconstructed.

## 6. Ghidra protocol `ghidra-5`

Additive over ghidra-4. Profile version 4 (adds caps; output limit 4 MiB, up from
2 MiB, because control-flow data can approach the old limit at the 16-function
detail bound). Validators reject any ghidra-5 field under ghidra-1–4, and the
serializer keeps historical shapes. `schemas/ghidra-analysis-v4.schema.json` is
frozen; `-v5` is new and equals the model schema.

Per function (inventory level):

- `thunk_target`: Ghidra's own `getThunkedFunction(true)` entry.
- `pointer_slots` (≤ 4): initialized, non-instruction memory with a non-flow
  reference to the entry (IAT entries, GOT entries, init arrays, unwind data),
  with reference type. Scan capped at 4096 incoming references.

Per selected function:

- `basic_blocks` (≤ 128) from `BasicBlockModel`: inclusive range, instruction
  count, `terminal` (last instruction's flow), flows (≤ 8) classified as
  `fallthrough`, `conditional_jump`, `unconditional_jump` or `computed_jump`,
  with `internal` (target inside the body). Call flows are excluded here.
- `basic_block_count` (stops at 4096), `instruction_count` (stops at 65536).
- `call_sites` (≤ 128, scan ≤ 4096 instructions): `direct`/`indirect` from the
  instruction flow type; a `target` only when Ghidra recorded a call reference
  (`target_basis: ghidra_call_reference`). Otherwise the target is null and stays
  unresolved.

New Ghidra runs must produce ghidra-5. Stored ghidra-1–4 outputs remain readable.
Their structure reports `not_captured`, and their import-slot join reports
`not performed` with the reason. Selected-function inspections of a ghidra-4 run
are refused as `ghidra_incompatible`, as v0.9 already did for profile changes.

## 7. Cross-tool joins (graph-2)

| Edge type | Strength | Basis | Rule |
|---|---|---|---|
| `external_symbol_import_slot` (new) | `exact_offset_equality` | `lief_import_address_table` or `lief_elf_relocation_load_segment` + `ghidra_memory_block_file_bytes` | A Ghidra pointer slot of an external function (its entry, or its thunk target) and a LIEF import slot translate to the same file offset, each through its own basis. Names are recorded (`names_equal`), not required. |
| `target_within_string_occurrence` (new) | `offset_containment` | `ghidra_memory_block_file_bytes` + `strings_step_file_range` | A string-data reference target lies strictly inside a strings-step occurrence's exact byte range. Used only when no occurrence starts at that offset. |
| `calls` (extended) | `exact_reference` | `ghidra_call_site` (+`ghidra_call_reference` for indirect) | Call sites whose recorded target is an inventory function. Unresolved calls are only counted. |
| `yara_match_in_function_body` (extended) | `address_containment` | unchanged | Adds `length` and `last_byte_in_same_body`: whether the last matched byte maps into the same body. |

Join taxonomy in coverage: `import_slot` reports `lief_slot_without_ghidra_pointer`,
`no_import_slot_at_offset`, `target_not_external`, `ordinal_only_slot` and
translation states. Weak joins remain weak: `external_symbol_named_as_import`
stays `name_equality` and is never promoted.

**Real-data validation of the import-slot join.**

- `hello_v1-x86_64.elf`: all 6 LIEF slots (5 `GLOB_DAT`, 1 `JUMP_SLOT`) join
  Ghidra's pointer slots. Ghidra reports `puts`'s slot at `ram:00104000`; LIEF's
  JUMP_SLOT relocation is at VA `0x4000`, offset 12288. The two agree, which
  independently confirms Ghidra's ELF PIE base of `0x100000`.
- `capa_read_file-x86_64.exe`: 32 of 36 IAT slots join. The test checks every
  edge offset against `lief.PE.Binary.rva_to_offset(iat_rva)`. 4 LIEF slots have
  no Ghidra pointer slot and are reported as `lief_slot_without_ghidra_pointer`.

**Not enabled: capa ELF function joins.** capa/vivisect's ELF load base is still
unverified against real ELF fixtures, and the bundled authored capa rules target
PE. The join keeps reporting "not performed" with the v0.10 reason. The ELF
program-header mapping added here is the loader's mapping, not capa's, so it is
not used for capa addresses.

## 8. API

See `docs/api-v0.11-deep-evidence.md`. New read-only endpoints:

- `GET /reviews/{id}/evidence`, `…/evidence/nodes`, `…/evidence/edges`,
  `…/evidence/nodes/{node_id}`
- `GET /evidence/compare?a=…&b=…`
- `GET /sample-versions/{id}/structure`
- `GET /runs/{id}/ghidra/functions/{index}/structure`

New problem code `evidence_not_captured` (409). All collections are paginated with

comparisons refuse cross-project sides; node detail ≤ 1 MiB, comparison pages
≤ 4 MiB, structure pages ≤ 500 rows.

## 9. Security

- No new execution path. Every new value comes from stored, digest-verified
  outputs: the LIEF child's output (already produced in the isolated, resource-
  limited child), the Ghidra output (fixed script, offline container) and existing
  database rows.
- The new extractor code runs inside the existing Ghidra script under the same
  monitor, CPU, memory, wall-clock and output limits. Each loop is bounded and
  cancellable.
- All new result models are strict (`extra=forbid`, typed, length-capped,
  non-negative offsets). Malformed ghidra-5 structure (a call target without
  its basis or a basis without a target, an unresolved flow that is not computed
  or claims to be internal, structure on an inventory-only function, or a block
  count below the retained blocks) is rejected.
- Exports keep labels out unless the user includes technical details, original
  names and string values. Masking is still applied.
- Fixture-only intake, the manifest, pre-parser authorization and I1 are unchanged.

## 13. Known limitations

- Deep tables exist only for imports made with adapter 0.3.0; existing versions
  need a new import (a new sample, under the unchanged admission policy).
- The import-slot join requires a ghidra-5 run. Ghidra retains ≤ 4 pointer slots
  per function, and functions beyond the inventory cap have none.
- Function correspondence across different files relies on unique non-default
  names. Stripped binaries mostly yield `no_stable_correspondence`. Structural
  similarity matching is future work, not guessed here.
- Strings appear in the graph only when Ghidra references them (v0.10 design).
  The full string list of a review remains in its `strings` field and in the
  existing version comparison.
- capa ELF joins remain disabled (§7). YARA matches still use evidence rows' first
  byte for containment; the last byte is reported, not required.
- Structure attributes count retained blocks for branch counts; totals are in
  `basic_block_count`.
- Linux/AMD64 host runs, hosted CI for the real lanes, and I1 remain open.
- The pre-existing cancellation timing race
  (`test_cancelling_a_running_run_kills_the_child`) is unchanged; see v0.10 §16.
