## Implemented review contract

- Profile ghidra-static version 1; Ghidra 12.2 and JDK 25. Script/options SHA-256
  pinned at queue time and rechecked by the worker. Standard loader analysis
  defaults, one analysis CPU; no arbitrary scripts or configurable analyzers.
- At most 256 inventory records and first 16 function details, 64 instructions and
  64 direct call references per detailed function; pseudocode max 4096 characters.
  Parent JSON limit 2 MiB, pipe capture 64 KiB per stream, per-file limit 16 MiB.
  Native decompiler payload 1 MiB, heap 768 MiB, analysis deadline 60s/file,
  parent wall deadline 180s and child CPU 120s. Resource limits are controls,
  never a measure of safety or analysis completeness.
- Function body size is an address count supplied by Ghidra, not a contiguous
  byte range. Address-space identity is preserved; no offset conversion occurs.
- Unselected/failed decompilation, capped functions/instructions/calls/pseudocode,
  failed steps and missing data remain distinct. The output has explicit flags
  and profile-wide field availability/limitations. Imports/exports, resources,
  non-call references, debug facts, strings/data and section membership are not
  extracted by this Ghidra profile; existing LIEF/string views remain separate.
- Direct calls are static relationships within the selected instruction windows,
  never execution traces. Pseudocode is a reconstruction, never original source.
- Summary claims link to the exact stored invocation output. No malware verdict,
  probability, risk score, fabricated confidence or behavior inference is added.
  Hypotheses remain empty when no reviewed interpretation is implemented.
- Coverage denominator is the single requested Ghidra step (0/1 or1/1); it is
  not whole-program coverage. Function inventory caps and details limits remain
  separately visible. All counts are scoped to project/version/run.

## Review findings and remaining gaps

Independent review found and fixed: nonzero permitted/inheritable/ambient/
bounding Linux capabilities could bypass an effective-only test; address-space
identity must reject oversized values rather than truncate. Both fixes were
re-reviewed. Concurrent Tools health requests now share one bounded health
attempt. Real application.properties has hyphenated revision keys, which the
prior metadata parser incorrectly rejected; regression coverage was added.

No full cgroup-escape/host-containment review, disk-exhaustion attack, OOM-kill
campaign, every analyzer failure, power-loss recovery, native Windows/AMD64
support, Ghidra comparison/matching, user-selected detail reruns or full license
redistribution audit was completed. Existing worker recovery is reused and
regression-tested; a real crash/restart during Ghidra serialization was not
induced. Health cleanup retries once; analysis cleanup retries three times,
records only cleanup_pending on failure and leaves private residue for the
existing age-based startup sweep. Residue itself is not copied into logs.

Added/edited repository prose, code comments, tests and UI copy are English.
No staging, commit, reset, clean, branch switch, pull/fetch/push, tag, PR or GitHub
mutation was performed. Git inspection was read-only; all implementation changes
remain unstaged/uncommitted in the original checkout.
