## Delivered path

- Ghidra provider emits `ghidra-3`: exact outgoing instruction references to
  defined strings/data/external symbols, inclusive function-body ranges,
  coordinate spaces, types, provenance and explicit caps. Exact Ghidra thunks
  may resolve an external target with separate resolution provenance; original
  reference target is retained. No fuzzy symbol or proximity joins, and no
  address-to-offset conversion. References whose target is not the start of a
  defined data item or an external symbol (undefined memory, code, the interior
  of a data item) are omitted, not emitted as unresolved.
- At most 64 references from 64 retained instructions per selected function;
  body ranges retain at most 64. Inventory and selected-function budgets remain.
  API detail, pinned review and private derivative retain the same evidence
  provenance; UI provides bounded reference map and textual table/navigation.
- New review/export v2 contracts preserve historical readers and old schema files.
  Stored reviews are never rewritten. `investigation-1` answers are pinned from
  explicit reviewed rule IDs/import categories, not inferred from display text.
  New interpretations do not retroactively populate historical answers.
- LIEF adapter 0.2.0 adds bounded structural declarations, measurements,
  explanations and provenance. ELF interpreter, NEEDED, RPATH/RUNPATH, GNU_STACK,
  RELRO/binding and PIE declaration are distinct. PE resources/version strings,
  TLS callback VAs, debug kinds, signature presence, declared protection flags
  and independently range-checked parser overlay are retained. Signature validity,
  runtime protection efficacy and publisher identity remain unverified.
- Five authored function-scope capa API-feature rules cover process creation,
  HTTP requests, file reads, INI reads and dynamic library loading. Exact hashes,
  license, subset version and reviewed alternatives are recorded. Two original
  upstream rules remain. YARA remains five text/format rules; import categories
  are not substituted for code rules.
- Compare immutable reviews by sources, latest attempts, parameters, rules,
  observations, exact full pinned import inventories and unknowns. Compatible
  means same sample lineage or same hash, and same file format; it is not proof
  of semantic equivalence. Historical missing inventories suppress import deltas.
  A new result is explicitly not proof of a new program capability.
- Review and function-note histories have previous/next navigation. Combined
  review selection uses explicit newest-first windows of at most 200 runs;
  `run_offset` selects another window and refresh preserves it. No silent scan
  beyond the budget. A window may omit older metadata; missing sources remain
  visible. Concurrent new runs can shift offset-based pages; pinned results
  themselves stay immutable.
- Human preview renders exactly the derivative returned by the export API,
  alongside optional technical JSON. New answer fields follow observation and
  overview inclusion. Function names/target machine symbols are omitted from
  exports; reference previews require string-value inclusion. Structural values
  require both technical-details and string-value inclusion. Masking remains
  heuristic. Original local outputs are not deleted.
