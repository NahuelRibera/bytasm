- **Authoritative design:** [`PROJECT_BLUEPRINT.md`](../PROJECT_BLUEPRINT.md) rev 0.3, [ADR-0001](../adr/0001-stack.md); implementation choices in [ADR-0002](../adr/0002-v0.1-implementation-choices.md).

## M2: LIEF subprocess runner

- `bytasm.runner.supervisor.run_adapter` starts `python -I -m bytasm.adapters.metadata_lief` with an argv list (no shell), `stdin=/dev/null`, `start_new_session=True`, default `close_fds`, a private work directory as `cwd`, and the environment `{PATH, LC_ALL}` only. No `preexec_fn`.
- The child's first action (`bytasm.runner.child`) lowers `RLIMIT_AS` 1 GiB, `RLIMIT_CPU` 25 s, `RLIMIT_FSIZE` 32 MiB, `RLIMIT_CORE` 0. LIEF is imported only afterwards (tested in a fresh interpreter).
- The parent hashes and admits the bytes first. The child re-reads `upload.bin` (mode 0400, `O_NOFOLLOW`) and refuses to parse unless its SHA-256 equals the admitted one.
- stdout/stderr are drained concurrently with a 64 KiB cap each; overflow fails the run. 30 s wall-clock timeout → `SIGTERM` to the group → 2 s → `SIGKILL`.
- Only exit 0 + a regular `result.json` ≤ 32 MiB that passes the strict Pydantic schema (`bytasm.adapters.result`) and names the admitted SHA-256 is used. Exit 2 + exactly one known reason code is a rejection. Everything else (other codes, signals, timeout, orphans, unclosed pipes, invalid/oversized/symlinked result) is a failure, and the result file is not read.
- The CLI (`bytasm inspect`) now parses in this child too. Its JSON output is byte-identical to M1 for all eight fixtures and for the refusal case (checked against a snapshot taken before the change, and by the existing CLI tests).

**This is process and resource separation, not a security sandbox.** The child runs as the same user with the same files and network.

## M3: local API and persistence

- `bytasm serve`: one uvicorn process; refuses any non-loopback `BYTASM_HOST`; reads the input policy once from `BYTASM_INPUT_POLICY` (`fixtures` default; `self_built` only on Linux). Marks itself non-dumpable on Linux.
- Guards (pure ASGI middleware, before the body): loopback peer, `Host` allowlist (`127.0.0.1|localhost|[::1]:<port>`), foreign `Origin` / `Sec-Fetch-Site: cross-site` refused, `X-Bytasm-Request: 1` required on every non-GET/HEAD request. No CORS headers are ever sent. CSP and other security headers on every response.
- Import (`POST /api/v1/projects/{id}/imports`) follows blueprint §5.4.1 steps 1–12: `X-Bytasm-Import` (base64url JSON ≤ 8 KiB, `owned_or_built` only, unknown fields refused) validated before any body byte; `Content-Length` > 64 MiB → 413 unread; single parser slot → 503 + `Retry-After`; raw body read from ASGI `receive` to `more_body: false` with a hard limit, early signature check and streaming SHA-256; manifest check before any parsing; duplicate check; Bytasm's header checks; the M2 runner; all-or-nothing persistence; `finally` cleanup.
- Persistence: SQLite via SQLAlchemy/Alembic (tables: project, sample, sample_version, authorization_record, analysis_run, tool_invocation, section, symbol, report). Files in content-addressed stores `data/{blobs,outputs,reports}/sha256/aa/bb/<sha256>` (0400, directories 0700), never served directly. If anything fails after files were placed, the transaction rolls back and the files this request created are deleted. Start-up sweep removes temp dirs and unreferenced stored files older than 1 h.
- No job queue (not required for v0.1, ADR-0001 D3).

## M4: UI

React + TypeScript SPA served by the API: projects list, project detail (samples and versions), import page (input-policy disclosure, mode, fixed `owned_or_built` basis, attestation notice, client-side size/empty checks, fixed server messages with request ID), sample-version overview (identity with copyable SHA-256, declared filename marked untrusted, header values marked "declared in file", provenance and attestation, sections with entropy labelled as a measurement, imports, exports). A persistent banner and top-bar pill show the input policy. No login. All file-derived text is rendered as React text; ESLint bans `dangerouslySetInnerHTML`, `innerHTML`/`outerHTML` and `insertAdjacentHTML` (tested). The three local reference screenshots were only used as described in blueprint §5.10 and are not in the repository.

## M5: JSON report

`POST /api/v1/sample-versions/{id}/reports` re-verifies the stored file's and the stored adapter result's SHA-256 (mismatch → 409 `integrity_error`, nothing generated), builds the report from the database, validates it against the models, stores it by its own SHA-256, and records a `report` row. `GET /api/v1/reports/{id}/download` re-verifies the report file and serves it as an `application/json` attachment. Schema: [`schemas/report.schema.json`](../../schemas/report.schema.json), described in [`docs/report-format.md`](../report-format.md). Two exports of the same data differ only in `generated_at` (tested).

## Implementation-time questions Q1–Q8 (blueprint §5.4.1)

Pinned versions: uvicorn 0.54.x (h11), Starlette 1.10.x, FastAPI 0.162.x (see `backend/uv.lock`). Re-run the tests when these pins change.

| # | Answer | Evidence |
|---|---|---|
| Q1 | Bytasm reads the ASGI `receive` channel itself and accepts an upload only after `http.request` with `more_body: false`. With the pinned uvicorn/h11, an aborted upload (with or without `Content-Length`, and a body shorter than `Content-Length`) reaches the app as `http.disconnect`; it is rejected, nothing is persisted, no temp file remains, and the slot is released. | `tests/integration/test_api_live.py` (real uvicorn, raw sockets) |
| Q2 | The pinned uvicorn does **not** cancel the handler when the client disconnects during parsing. | Q3 | Cancelling the awaiting task, including inside the SIGTERM→SIGKILL grace period, still kills the process group and reaps the child (`finally` path). | `test_cancelling_*` in `tests/integration/test_runner.py` |
| Q4 | `killpg` removes the child and children it forked into the group (a leftover is killed and the run fails as `orphan_processes`). A descendant that calls `setsid()` **escapes** the group kill: if it keeps a pipe open the run fails (`output_not_closed`), otherwise it is not detected. | Q7 | The import endpoint never calls `form()`/`UploadFile`. The import endpoint enforces its own 64 MiB limit while streaming. | Source read; `test_streamed_upload_stops_being_read_at_the_limit`, `test_declared_oversize_is_refused_without_reading` |

## Release-gate work after M5 (2026-10-27)

- **Compose** (`compose.yaml`, `Dockerfile`, `.dockerignore`): one `api` service with the blueprint §8.2 v0.1 settings, listed in ADR-0002. `make compose-check` (`scripts/check_compose.py`) asserts them on the configuration Docker Compose resolves, and `tests/unit/test_compose_check.py` shows that the checker refuses each weakening. `scripts/check-container.sh` (run by `make compose-up`) checks what the kernel applied in the running container: UID, empty capability sets, `NoNewPrivs`, seccomp, read-only root, `noexec` `/tmp`, cgroup pids/memory/CPU limits, no Docker socket, and the `127.0.0.1` port. Run on linux/arm64 (Docker Desktop, macOS host): health reports `platform: linux` and `parser_memory_limit_enforced: true`.
- **Container mode** (ADR-0002, proposed row): the server listens on the container's own interface, so the loopback-listener guard is skipped in that mode only; `self_built` is refused there. Tests: `tests/unit/test_config.py` (`container_*`), `tests/integration/test_api_guards.py::test_container_mode_skips_only_the_listener_check`.
- **Dependency audit:** `make audit` runs the locked `pip-audit` 2.10.1 (its own `audit` group in `uv.lock`) over every locked Python package with hashes, then `npm audit --audit-level=high`. Result on 2026-10-27: no known vulnerabilities in either.
- **Demo:** `make demo` (`scripts/demo.py`, procedure and cleanup in [`docs/demo.md`](../demo.md)), run natively and against the container.
- **Narrow windows:** `frontend/e2e/responsive.spec.ts` checks every screen at 360 px for horizontal page overflow and axe violations.

### Review findings fixed

| Finding | Fix | Regression test |
|---|---|---|
| If the per-import work directory could not be created (for example a full disk), the parser slot stayed taken, so every later import got 503 until restart. | The slot is released and the request ends with `internal_error`. | `test_failure_to_create_the_work_directory_frees_the_parser_slot` |
| The result file was opened with a blocking `open()`. A process that escaped the group kill (Q4) could swap `result.json` for a FIFO after the `lstat` check and block the event loop. | `O_NONBLOCK`, then `fstat` must show the same regular file. | `test_result_path_swapped_for_a_fifo_is_refused_without_blocking` |
| An encoded NUL byte in a UI path (`/assets/%00x`) raised inside `Path.resolve()` and returned 500. | Treated as an unknown path (serves `index.html`). | `test_static_paths_never_leave_the_ui_bundle` |
| At 360 px the import form overflowed the window, and the sections table's scroll container was not keyboard-focusable (axe `scrollable-region-focusable`). | Form grid `minmax(0, 1fr)`, inputs capped at 100 %, 16 px gutters below 600 px; the scroll container is a labelled, focusable region. | `frontend/e2e/responsive.spec.ts` |
| Error messages did not always say what to do next. | Actionable text for `internal_error`, `host_not_allowed`, `origin_not_allowed`, `upload_incomplete`, `integrity_error`, and the UI's "API unreachable" message. | Existing problem-details tests |
